# Ralph ループ：1イテレーションの手順

あなたはこのリポジトリで**自律研究ループの1イテレーション**を実行する。前回までの記憶は無い。状態はすべてファイルと git にある。以下に上から順に従う。パスはリポジトリルートからの相対。

**モード**：起動時の指示に「ローカル」とあればローカルモード（PR を作らず、今のブランチにコミットするだけ）。指定が無ければ PR モード。

## 原則

- **1回1タスク**。小さく確実に進め、続きは次回に回す。
- 判断の根拠はファイルから取る。記憶や推測で埋めない。
- 「確かめた」と書けるのは、実行したコマンドとその結果を示せるときだけ。
- 痕跡（PLAN・journal、必要なら claims・NOTES）を残さずに終えない。次の自分はファイルと git log しか見ない。

## 0. 実行前チェック

`bash ralph/bin/preflight.sh` を実行する（ローカルモードでは `--local` を付ける）。

- 終了コード 3（`SKIP:` の行がある）なら、研究を始めずに `SKIP: <理由>` と1行報告して終了する。ファイルの変更もコミットもしない。
- `WARN:` は今回の journal に書き写してから先へ進む。未マージ PR を確認できなかったという WARN なら、GitHub のツールで open な PR を見て、タイトルが `[ralph]` で始まるものがあれば SKIP として終了する。

## 1. 状況把握

1. 必ず読む：`ralph/GOAL.md`、`ralph/RULES.md`、`ralph/PLAN.md`、`ralph/QUESTIONS.md`、`ralph/NOTES.md`、`ralph/claims.json`、`theory/CONVENTIONS.md`、`ralph/journal/` の番号が大きい方から3件、`git log --oneline -15`。
2. 今回触りそうなトピックの `theory/<topic>/README.md`（記号表）を読む。成果物がまだ無ければ GOAL.md の背景から辿れる資料を読む。大きな資料（論文 PDF など）はサブエージェントに読ませて要点だけ受け取る。
3. 出発点が健全か確かめる：`CHECK_FAST=1 tools/check_all.sh` と `python3 ralph/bin/lint.py` を実行する。
4. 今回のイテレーション番号 N を決める（`ralph/journal/` の最大番号 + 1。journal・査読レポートのファイル名に使う）。

## 2. 完了判定

GOAL.md の「完了条件」をすべて満たしているか、根拠を確かめながら判定する。

- **満たしていない**：手順3へ。
- **完了監査がまだ**（完了条件の他はすべて満たす）：今回のタスクは完了監査とする。referee サブエージェントにトピック全体を新しい目で通読させ（RULES.md「査読」）、レポートを `ralph/reviews/NNNN-audit.md` に保存する。NEEDS_WORK なら指摘を PLAN.md の「査読指摘」に移す。判定にかかわらず手順6へ（PASS なら次の回から「完了済み」になる）。
- **完了済み**（監査も PASS）：新しい研究はしない。校閲パスを1回だけ行う（誤字・数式の整合・リンク切れ・`tools/check_all.sh` の再実行）。直すものが無ければ「完了状態を確認、作業なし」の journal だけ書いて手順7へ。最終報告は `COMPLETE:` で始める。

## 3. タスク選択

上から順に、当てはまる最初のものを**1つ**選ぶ。

1. `tools/check_all.sh` の FAIL か `lint.py` の ERROR（壊れた状態の修復が最優先）
2. PLAN.md「最優先（人間）」の指示
3. QUESTIONS.md で回答が書き込まれ、まだ反映していない質問
4. PLAN.md「査読指摘」
5. PLAN.md「必須」の未完了のうち、他のタスクの土台になるもの
6. 「必須」が空、または人間が再計画を指示している → **計画イテレーション**：研究はせず、GOAL.md のコアの問いと完了条件を1回1つ程度の大きさのタスクに分解して PLAN.md に書き、各問いの結論となる主張の枠を `ralph/claims.json` に `draft` で置く（`location` は書く予定のファイルでよい）
7. PLAN.md「発展」

選んだら次を確かめる。

- journal と git log を見て、直前の実行と重複していないか。
- **空回りの防止**：同じタスクが直近2回の journal で未完のままなら、3回目は手を付けない。詰まった内容を QUESTIONS.md に書き、PLAN.md でそのタスクに「保留（質問n）」と付けて、次の候補に移る。
- 1回で終わらない大きさなら、PLAN.md 上で分割して最初の一片だけをやる。

## 4. 実行

- RULES.md（特に「誠実さ」）に従って研究・執筆する。
- 試行錯誤や途中計算は `idea/` に置き、確定した論理だけを `theory/` に置く。
- 新しい記号・単位・符号の約束は、使う前に `theory/CONVENTIONS.md` とトピックの記号表で確かめ、新設したらそこに書き足す。
- 行き詰まったら結論を急がない。質的に異なる進め方を2つ以上 `idea/` に書き出して比べる。人間の判断が要る事項は QUESTIONS.md に書いて別のタスクに移る。

## 5. 検証と査読

1. 閉じた式・結論を出したら、RULES.md「検証」に従って数値検算と既知の極限・特殊ケースへの帰着を `tools/<topic>/check.sh` から走るようにする。
2. `tools/check_all.sh`（`CHECK_FAST` なしのフル）を実行する。FAIL が残るなら、`theory/` の変更を `idea/` に退避するか直すまで、その主張を `checked` にしない。
3. `theory/` に結果を足した・直したときは、**referee サブエージェントに査読させる**（依頼文の型は RULES.md「査読」）。返ってきた判定と本文を `ralph/reviews/NNNN-<短い名前>.md` に保存する（NNNN は今回の journal と同じ番号）。
   - `PASS`：該当する主張の `status` を `refereed`、`review` にレポートのパスを書く。
   - `NEEDS_WORK`：この回で直せる指摘は直して再査読する（再査読は1回まで）。残りは PLAN.md「査読指摘」に移し、主張は `checked` に留める。
   - サブエージェントが使えない環境では、`.claude/agents/referee.md` の手順で自分で点検し、レポートに「セルフレビュー」と明記する。この場合は `refereed` にしない。

## 6. 記録

- **PLAN.md**：完了したタスクを `[x]` にして「完了」節へ移す。見つかった新タスクを適切な節に足す。「最優先（人間）」の指示は反映したら消す。
- **claims.json**：新しい主張を足し、`status` を更新する。主張は消さない（誤りと分かったら `refuted` にして理由を `note` に書く）。
- **QUESTIONS.md**：回答を反映した質問の見出しに「（反映済み）」を付ける。
- **NOTES.md**：今回わかった「駄目だったやり方とその理由」「落とし穴」があれば1〜2行で足す。古くなった項目は消す・まとめる（100 行以内）。
- **journal**：`ralph/journal/` に**新しいファイルを1つ**作る（書式は RULES.md「journal」）。既存のエントリは書き換えない。
- 最後に機械チェックを通す。PR モードでは `python3 ralph/bin/lint.py --base origin/<ベースブランチ> --loop`、ローカルモードでは `python3 ralph/bin/lint.py`。ERROR が残っていれば直してからコミットする。

## 7. コミットと終了

- **PR モード**：変更をコミットしてプッシュし、PR を作る（メッセージ・タイトル・本文・マージ方針は RULES.md「Git」）。ブランチ名は実行環境の流儀に従ってよい。
- **ローカルモード**：今のブランチにコミットする。push と PR はしない（push は ralph/loop.sh が各回の後に行う）。
- 最後に報告して終わる。報告の1行目は `DONE:`（今回やったこと）、`SKIP:`（理由）、`COMPLETE:`（完了状態）のどれかで始め、2〜3行目に次回の推奨タスクを書く。
