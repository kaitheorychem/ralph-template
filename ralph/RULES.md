# 規約

Ralph ループのイテレーションだけでなく、このリポジトリで研究作業をするすべてのセッションが従う。パスはリポジトリルートからの相対。

## 作業単位

- 1イテレーション = 1タスク。大きなタスクは PLAN.md 上で分割してから着手する。
- 迷ったら小さい方を選ぶ。1つの .md ファイルに閉じる変更が理想。
- 人間の判断が必要な事項（理論の方向転換、既存結果と矛盾する発見、先行研究の解釈が分かれる点など）は勝手に決めず、`ralph/QUESTIONS.md` に書いて別のタスクに移る。

## 配置と命名

- 研究成果は `theory/` に置く。トピックごとにディレクトリを切り、名前は連番2桁＋英小文字とアンダースコア（例：`theory/00-basic_model/`）。
- 下書き・途中計算・没案は `idea/` に置く。`theory/` には確定した論理だけを置き、書きかけを残さない。役目を終えた idea メモは本文化したイテレーションで削除してよい。
- `refs/` は人間が管理する先行研究置き場。読むのは自由だが書き換えない。
- 完成済みの既存トピックは原則書き換えない。例外は新トピックへの参照リンクの追記など軽微なもののみ。
- `ralph/` 内でエージェントが書き換えてよいのは PLAN.md、QUESTIONS.md（質問の追記と「反映済み」の付記のみ）、journal/（新規ファイルの追加のみ）。
- ルートの README.md と CLAUDE.md は人間が管理する。

## 執筆スタイル

- 各トピック直下に README.md（概要・ファイル一覧・記号の一覧・要点）を置き、個別の内容は独立した .md に分ける。
- 数式は LaTeX（`$...$`、`$$...$$`）。
- 文体は「だ・である」調の簡潔な説明文。
- 既存トピックで定義済みの記号は引き継ぐ。新しい記号を導入するときは初出で必ず定義し、トピック README の記号一覧にも載せる。既存の記号と衝突させない。
- 結論には導出を付ける。導出が長くなる場合はファイルを分け、README から流れが追えるようにする。
- 先行研究と重なる結果には出典を明記し、何が既知で何が新規かを区別する。

## 検証

- 閉じた式を出したら、具体的な数値例を最低1つ入れて検算する。
- 既知の結果が得られる極限・特殊ケースがあれば、そこに帰着することを必ず確認し、本文にも明記する（具体的なチェック内容は下の「プロジェクト固有の規約」で定める）。
- **数値的な検証（検算）を行ったら、使い捨てにせず、使ったコードを必ず `tools/` 以下に残す**。あとから他のイテレーションや人間が同じ検算を再実行・再利用できるようにするため。「乱数◯万試行で確認したがコミットせず」で終わらせない。
  - トピックに対応する `tools/<topic_name>/` があればそこに検算スクリプト・関数を追加する。まだ無ければ新設する。
  - 理論の式を使わない独立な基準（直接計算・数値積分など）と閉形式を突き合わせる形にする。乱数を使う場合はシード付きで再現可能にする。
  - 使い捨てで書いたスクリプトでも、結論の根拠になったものはそのイテレーション内で `tools/` 配下に整理して置いてからコミットする。単発の手計算の確認程度で再利用の見込みが無いものまで無理に残さなくてよい（判断に迷ったら残す側に倒す）。
- 各 `tools/<topic_name>/` には README.md を置き、次の2つを必ず書く：
  - **「検査の実行」節**：そのトピックの検査を全部走らせる**1つのコマンド**（全数一致なら終了コード 0、不一致があれば非 0 で終わるようにする）。検査を追加したらこのコマンドから走るようにする。
  - 各検査がどの理論ファイルに対応するかの表。

## journal

- 1イテレーション = `ralph/journal/` の1ファイル。既存のファイルは書き換えない（誤りに気づいたら次のエントリで訂正を書く）。
- ファイル名：`NNNN-YYYY-MM-DD.md`。`NNNN` はイテレーション番号（既存ファイルの最大番号 + 1、4桁ゼロ埋め）。
- 各項目は3行以内、全体で20行以内に収める。詳しい導出や数値は theory / idea / tools の該当ファイルに書き、journal からはリンクするだけにする。
- フォーマット：

```markdown
# イテレーションN：タスクの短い名前（YYYY-MM-DD）

- やったこと:
- 結果・分かったこと:
- 次にやるべきこと:
- 未解決の疑問:
```

## Git

- コミットメッセージ：
  - 理論本体の変更 → `theory/<トピック番号>: <やったこと>`
  - ループ運用ファイル（PLAN / QUESTIONS / journal）だけの変更 → `ralph: <やったこと>`
  - tools/ の検算コードの変更 → `tools: <やったこと>`
- 動く状態・読める状態でコミットする。`theory/` に書きかけを残す状態でイテレーションを終えない（続きものは `idea/` に退避して次回拾う）。
- **プルリクエストのタイトルは `[ralph] ` で始める**（未マージ PR の検出に使う。PROMPT.md 手順1）。
- **プルリクエストのベースブランチは `main`**。
